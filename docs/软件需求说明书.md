## 项目概述

### 软件系统描述

系统采用 B/S 架构，部署于 Linux 课程服务器：

```
浏览器 ← HTTP/JSON → server (C11 + libmicrohttpd) ← SQLite3
                          │   ├─ db.c     关系表（users 等）
                          │   └─ kv_store 目录式 KV（namespace → kv_{ns} 表，存题目数据）
                          ↕ libcurl (API 代理)
                      大模型 (OpenAI 协议)
```

前端为纯 HTML/CSS/JS 静态页面，由 C 服务端直接托管，零构建工具链。后端采用模块化分层架构：路由层（routes.c）→ 业务层 → 数据层（db.c）→ 存储层（kv_store），AI 层（ai_client.c）独立代理大模型调用。

### 用户认证模块

#### F-01 登录

| 属性 | 值 |
|------|-----|
| 优先级 | P0 - 必须 |
| 接口 | `POST /api/v1/auth/login` |
| 输入 | `{"username":"...", "password":"..."}` |
| 输出 | `{"token":"...", "user":{"id", "username", "name", "role"}}` |
| 错误 | 400/401/500 |

**详细规则**：
- 密码使用 SHA-256(salt || password) 哈希比对
- 用户名不存在与密码错误均返回 401，防枚举攻击
- 成功登录后创建 64 位十六进制 Token，有效期 24 小时
- 预设 Demo 账号：admin(admin123)、teacher(teacher123)、student(student123)

### AI 智能解答模块

#### F-09 AI 解答生成

| 属性 | 值 |
|------|-----|
| 优先级 | P0 - 必须 |
| 接口 | `POST /api/v1/chat` |
| 鉴权 | Bearer Token |
| 说明 | 后端代理调用大模型，构建 Prompt 上下文（题干+选项+答案），API Key 不出后端 |

**AI 解答流程**：
1. 题目进入题库
2. 教师开启 AI 解答并配置参数（模型、temperature、max_tokens、Prompt 模板）
3. 系统构建上下文
4. 调用大模型获取解答
5. 返回结构化解答

**当前实现状态（2026-10-12）**：后端 AI 对话接口（`POST /api/v1/chat`，`ai_completion()`）尚未实现；前端对话页已就绪，对 404/405/501 及网络异常自动降级为内置演示数据并在界面标注「非真实 AI 生成」，接口就绪后无需改动前端即可联通。

## 非功能需求

### 性能需求

| 指标 | 要求 |
|------|------|
| API 响应时间 | < 200ms（不含 AI 调用） |
| AI 调用 | 异步处理，超时 30s |
| 并发 Session | 最多 128（Demo 阶段） |

### 外部接口需求

#### 用户接口

- 前端为纯 HTML/CSS/JS，由 C 服务端直接托管
- 浏览器访问 `http://<IP>:8000`
- 交互方式：SPA hash 路由，支持在线 + file:// 离线双模式

#### 硬件接口

无特殊硬件接口要求。部署于通用 x86_64 Linux 服务器。

#### 软件接口

| 接口 | 说明 |
|------|------|
| libmicrohttpd | HTTP 服务框架，守护进程模式 |
| SQLite3 | 关系数据持久化（用户与题目均经 kv_store 存取） |
| kv_store（内部模块） | 目录式键值存储层：namespace 映射 SQLite 表 `kv_{ns}`，`(key_name, value_name)` 复合主键，见 `docs/kvstore.md` |
| libcurl | AI API 代理调用（OpenAI 协议） |
| cJSON | JSON 解析/生成（MIT 协议单文件库） |
| OpenSSL libcrypto | SHA-256 密码哈希 |

#### 通信接口

- HTTP/1.1，Content-Type: application/json
- 鉴权：Bearer Token (Authorization header)
- 所有 API 路径前缀：`/api/v1/`
- 错误统一返回 JSON：`{"error": "描述信息"}`
- 状态码语义：401（未认证）、403（无权限）、404（资源不存在）、400（参数错误）、500（服务器内部错误）

### 设计约束

- **C11 标准**：`gcc -std=c11 -Wall -Wextra` 零警告编译
- **内存安全**：malloc/free 严格配对，禁止泄漏/越界/悬垂指针；kv_* 返回值按约定释放（char* 用 free()，char** 用 kv_free_str_array()）
- **存储分层**：用户与题目数据统一走 kv_store 目录式存储（users / qdata namespace）；关系型辅助数据（如配置）走 db.c
- **API Key 不出后端**：所有大模型调用由 server 代理
- **多租户隔离**：所有业务查询必须带当前用户/所属教师上下文
- **路径穿越防护**：静态文件服务拒绝含 `..` 的路径
- **无硬编码密钥**：敏感信息一律走环境变量
- **并发预留**：保持无共享可变状态，路由处理函数无副作用

### 质量属性

| 属性名称 | 详细要求 |
|----------|----------|
| 正确性 | 所有 API 接口严格符合 api.md 定义，CI 冒烟测试全部通过 |
| 健壮性 | 无效输入返回 400 + JSON 错误信息；AI 服务不可用时降级提示，不崩溃 |
| 安全性 | 密码 SHA-256 哈希；HTTPS（生产环境）；SQL 注入防护（参数化查询）；登录防枚举攻击 |
| 可用性 | 系统高可用（Demo 阶段单实例可接受）；服务异常时优雅降级 |
| 可维护性 | 模块化分层架构（路由/业务/数据/存储/AI）；monorepo 扩展支持；详细日志（debug.h，-DDEBUG 开关） |
| 可移植性 | 目标平台 Ubuntu/Debian Linux；代码 C11 标准跨平台（CI 验证） |

### 术语表

| 术语 | 说明 |
|------|------|
| 分支对话树 | 以题目为根的可 Fork 多路径讨论结构 |
